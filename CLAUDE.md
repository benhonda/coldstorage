### Monorepo structure

Currently one product, **ColdStorage** (see the root [`README.md`](./README.md) for the full picture — orientation, state of the world, dev gotchas; [`PROD.md`](./PROD.md) is the active going-to-prod plan; [`MIGRATION.md`](./MIGRATION.md) records the completed AWS account move):

- `coldstorage/` — the Swift package: portable `ColdStorageCore` (engine, journal, crypto, control plane) + `ColdStorageMac` adapter (PhotoKit, FSEvents) + executables (`coldstored`, `coldstorectl`, `coldstore-cli`, `coldstore-restore`, `coldstore-photo-picker`). Docs: `coldstorage/README.md` (run it) + `coldstorage/DESIGN.md` (engine design + portable/Mac module split).
- `ui/` — the Electron/React control panel, a thin client over the daemon's control socket (Taskfile `ui:*`). Docs: `ui/DESIGN.md` (UX + daemon contract) + `ui/PACKAGING.md`.
- `account-backend/` — Hono API on Vercel + Neon/Drizzle: Cognito↔Paddle↔zero-knowledge-key-blob backend for the multi-user/paid layer (Taskfile `backend:*` + `link:account-backend`/`pull:account-backend`; see [`PROD.md`](./PROD.md) Phase 4). **Phase 4 gate MET 2026-07-02; PRODUCTION LANE LIVE 2026-07-10** — both lanes deployed and smoke-tested: staging at `api-staging.coldstorage.sh` (sandbox Paddle, proven via simulator), production at `api.coldstorage.sh` (live Paddle catalog + webhook destination, prod Neon, all three prod secrets real — see `PROD.md` Phase 4). Residual: a *matching* webhook secret is only provable by the first live event's 200 in Paddle's notification log.
- `site/` — the marketing website + `/checkout` page (RR7/adpharm-stack on Vercel; Taskfile `dev:site`/`typecheck:site`/`link:site`/`pull:site`). **LIVE at `coldstorage.sh`.** **`site/` is the single source of truth for the whole site** — tokens (`app/styles/ds/`), DS components, marketing sections, copy: edit any of it here, freely. Claude cloud design (a DS project + a marketing project) is an **import source**, not an upstream owner: pull a section/component down when you want one, translate it in, and it becomes ordinary repo code. No mirror, no sync, no reconciliation. Docs: [`SPEC.md`](./site/SPEC.md) — the build + design-import architecture (the SSOT for this app). `/checkout` is the branded Paddle overlay page, re-homed from account-backend.
- `infra/coldstorage/` — Terraform/Terragrunt for S3 GDA + lifecycle + least-priv daemon IAM + Cognito (Taskfile `tf:coldstorage:*`; **APPLIED + verified in Ben's own AWS account** (migrated off Adpharm 2026-07-27, old stacks destroyed — see `MIGRATION.md`) — prod vault + Cognito + the pre-sign-up Lambda + the managed-login custom domain `auth.coldstorage.sh` (`auth-domain.tf` — so Google's consent screen names a host we own rather than `amazoncognito.com`; it owns a us-east-1 ACM cert and the two Vercel DNS records those need). No daemon IAM user: the daemon authenticates as the signed-in user via Cognito STS and holds no standing credential. R2 still deferred until the thumbnail view needs it). Also here: the branded one-time-code email — a `custom_email_sender` Lambda + its KMS key in `lambda.tf`, sending through CD2 from `m.coldstorage.sh` in place of Cognito's own mail (see `infra/coldstorage/README.md`).
- `infra/account-backend/` — Terraform/Terragrunt for the account-backend's Vercel project: production + **staging** (the sandbox-Paddle case — a stable deployed URL + its own DB, isolated from real subscriptions), OIDC role + TF-managed env vars, Cognito ids read from `infra/coldstorage` (Taskfile `tf:account-backend:*`). **APPLIED for both stacks** (in Ben's own account since 2026-07-27 — see `MIGRATION.md`); the manual secrets are set for real on both lanes (production's on 2026-07-10 — `PROD.md` Phase 4). `modules/shared` now owns the account-level Vercel OIDC provider, which `infra/site` reads via a `dependency`.
- `infra/site/` — Terraform/Terragrunt for the marketing site's Vercel project (Taskfile `tf:site:*`): a dormant OIDC role + the two `PUBLIC_PADDLE_*` env vars, production + staging. **APPLIED + live** (in Ben's own account since 2026-07-27 — see `MIGRATION.md`). Simpler than account-backend — no Cognito/DB/secrets. The `coldstorage.sh` zone lives in Vercel, never Route53, and this component manages none of it — its apex/www records are ones Vercel writes for itself. The only TF-managed records anywhere are the two in `infra/coldstorage`'s `auth-domain.tf`, whose values that plan computes.
- `phase0-upload-spike/`, `phase0-photos-spike/` — de-risking spikes (both run + proven; seeds of the core).
- `Taskfile.yml` — the single root command surface (`daemon:*`, `ui:*`, `backend:*`, `dev:site`/`typecheck:site`, `tf:coldstorage:*`, `tf:account-backend:*`, `tf:site:*`, `link:*`/`pull:*` for Vercel projects). Use it for everything. Its `vars:` block is also the **SSOT for the deploy-target constants** (`AWS_PROFILE`, `AWS_REGION`, `COLDSTORE_TF_STATE_BUCKET`, `COLDSTORE_VERCEL_TEAM_SLUG`) — the `infra/*/root.hcl` files read them back via `get_env`, so an account/team move is a change here and nowhere else. `start`/`dev`, `tf:plan`/`tf:apply`/`tf:init` and `link`/`pull` (no suffix) are interactive pickers over the namespaced tasks — same `read`/`select` + `case` convention throughout, not flag-passing.
- `strategy/` — **gitignored, private**: product spec, brand voice, economics. Not in the public repo.
